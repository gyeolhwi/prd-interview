## 작업 요약

답을 고른 뒤 다음 질문이 뜨기까지 걸리는 시간을 줄였습니다. 질문을 도구 호출 대신 구조화 출력으로 받게 바꿔 답 뒤의 `"완료"` 응답 턴과 `waiters` 구조를 없앴고, Claude 프로세스 종료를 기다리지 않게 했습니다. 화면 폴링도 0.5초로 줄였습니다.

## 성능 비교

| 지표 | 전 | 후 | 변화 |
| --- | ---: | ---: | ---: |
| 답 → 다음 질문 (서버, 3회 중앙값) | 10,068ms | 7,726ms | **-23%** |
| 답 1회당 Claude 호출 | 3 (채점 + 질문 + "완료" 턴) | 2 (채점 + 질문) | -1 |
| 호출 1회당 프로세스 종료 대기 | 약 800ms | 0 (백그라운드) | |
| 화면 폴링 간격 | 1,500ms | 500ms | 평균 대기 -0.5초 |

측정: 같은 아이디어로 세션을 만들고 첫 번째 선택지로 3회 답한 뒤, 답한 순간부터 다음 질문이 저장될 때까지의 시간을 쟀습니다(실제 Claude 호출). 원본은 `.issue/3/evidence/before.txt`, `after.txt` 에 있습니다. 모델 응답 시간이 매번 달라서 같은 측정을 다시 해도 ±1초 정도 흔들립니다.

## 남은 병목

after 기준으로 채점(`score`)과 질문 생성(`ask`)이 각각 약 3.5~4초씩 **순서대로** 돕니다. 이 둘을 Claude 호출 하나로 합치면 3초 이상 더 줄일 수 있지만, 지금 코드가 정하는 "다음에 물을 항목"을 모델에게 맡기게 되어 이번 범위에서 뺐습니다. Haiku 모델은 짧은 요청에서 기본 모델보다 빠르지 않았습니다(1.9초 vs 1.8초).
