# 취소한 주문도 '취소됨'으로 보이게 하기 유지보수 Pre-PRD

- **한 줄 요약:** 고객 화면의 주문 목록과 주문 상세 화면에서 취소한 주문도 '취소됨' 글자와 함께 보이게 해서, 고객이 취소 사실과 환불 진행 상태를 직접 확인할 수 있게 합니다.
- **모호도:** 바뀌는 것 0.8 · 이유 0.7 · 요청자 0.6 · 고객 0.8 · 안 하는 것 0.9 · 성공 확인 0.7 · 확인 0.5 (평균 0.69)
- **작성일:** 2026-11-23
- **상태:** 확정

## 1. 무엇이 바뀌나요?

- **지금까지:** 고객이 주문을 취소하면 고객 화면의 주문 목록에서 그 주문이 사라져 보이지 않았습니다.
- **앞으로:** 취소한 주문도 원래 주문 날짜 자리에 그대로 보이고, '취소됨'이라는 글자가 함께 표시됩니다. 주문 상세 화면에서는 환불이 어디까지 진행됐는지 볼 수 있습니다(보기만 가능).
- **바뀌는 곳:** 고객이 보는 주문 목록 화면, 주문 상세 화면

## 2. 왜 이 기능이 필요한가요?

- 취소한 주문이 목록에서 사라져서 "주문이 없어졌다"는 고객 문의가 들어오고, 여기에 답하기가 어렵습니다.
- 가장 최근에도 고객이 환불이 됐는지 확인해 달라고 요청해 곤란했던 일이 있었습니다.
- 이런 문의가 하루에 몇 번씩 들어옵니다.
- 이대로 두면 문의에 답하느라 시간을 계속 낭비하게 됩니다.

## 3. 요청자는 무엇이 필요한가요?

- **요청자:** 고객 문의에서 시작된 요청입니다("주문이 사라졌다"는 문의).
- **꼭 필요한 것:** 고객이 주문이 취소됐다는 사실을 직접 확인할 수 있어야 합니다. 목록에서 취소된 주문을 한눈에 알아볼 수 있으면 됩니다.

## 4. 고객은 어떤 점이 좋아지나요?

- **영향받는 고객:** 주문을 취소한 고객
- **좋아지는 점:** 문의하지 않아도 취소 사실을 직접 확인할 수 있습니다. 주문 상세 화면에서 환불이 어디까지 진행됐는지도 볼 수 있습니다.

## 5. 이번에 안 하는 것

- 관리자 화면은 바꾸지 않습니다.
- 취소된 주문에 '다시 주문하기' 버튼은 넣지 않습니다.
- 취소된 주문을 색이나 모양으로 다르게 꾸미지 않습니다('취소됨' 글자 표시만 합니다).
- 고객이 화면에서 환불을 요청하거나 바꾸는 일은 넣지 않습니다(환불 상태는 보기만 합니다).

**제약**
- 결제와 환불 처리에는 절대 영향을 주면 안 됩니다.
- 이번 주 안에 바뀌어야 합니다.
- 앞으로 취소하는 주문뿐 아니라 최근에 이미 취소된 주문도 보여야 합니다(얼마나 예전 주문까지 보일지는 아직 정하지 않았습니다).

## 6. 잘 됐는지 어떻게 아나요?

- **성공 기준:** 고객 화면의 주문 목록에 취소한 주문이 '취소됨'으로 보이고, 주문이 사라졌다는 문의가 거의 없어지면 성공입니다.
- **확인 방법·시점:** 바꾼 바로 그날, 직접 주문했다가 취소해 보고 목록에 '취소됨'으로 보이는지 확인합니다.

## 7. 확인된 결정

| 결정 | 이유 |
|---|---|
| 취소한 주문은 목록에서 원래 날짜 자리에 그대로 보여 준다 | 고객이 자기 주문을 원래 있던 자리에서 바로 찾을 수 있게 하려고 |
| 고객이 보는 화면만 바꾸고 관리자 화면은 그대로 둔다 | 문의가 고객 쪽에서 나왔고, 관리자 화면은 이번에 하지 않아도 되는 일로 정했기 때문에 |
| 취소 주문은 '취소됨' 글자로만 구분한다 | 글자 표시만으로도 한눈에 알아볼 수 있다고 확인했기 때문에 |
| 주문 상세 화면도 함께 바꾼다 | 주문 목록 말고도 같이 바뀌어야 할 곳으로 꼽혔기 때문에 |
| 앞으로 취소하는 주문뿐 아니라 최근에 이미 취소된 주문도 보여 준다 | 앞으로 취소하는 주문만 보이면 예전에 취소한 주문 때문에 문의가 계속 생길 수 있어서 |
| 환불 진행 상태는 고객이 보기만 할 수 있게 한다 | 결제·환불 처리에는 절대 영향을 주면 안 되기 때문에 |
| '다시 주문하기' 버튼은 이번에 넣지 않는다 | 이번에 빼도 되는 일로 정했기 때문에 |
| 이번 주 안에 바꾸고, 바꾼 그날 직접 주문했다가 취소해 보며 확인한다 | 요청자가 원한 일정과 확인 방법이라서 |

## 8. 남은 질문

1. 바뀌는 것: 앞으로 어떻게 바뀌나
2. 이유: 안 바꾸면 무엇이 계속 손해인가
3. 요청자: 누가 요청했나
4. 요청자: 요청자에게 꼭 필요한 것
5. 고객: 고객이 체감할 변화
6. 성공 확인: 눈으로 확인할 성공 기준
7. 성공 확인: 확인 방법·시점
8. 모순: [고객] 단계에서는 '앞으로 취소하는 주문만' 보이게 하자고 했는데 [확인] 단계에서는 '최근 것도 보이게'로 바꿨고, 얼마나 예전 것까지 보여 줄지는 정하지 않았습니다.
9. 모순: [성공 확인] 단계에서 문의가 '거의 없어지면' 성공이라고 했는데, 결과는 '바꾼 바로 그날' 확인한다고 해서 문의가 줄었는지는 그날 알 수 없습니다.
